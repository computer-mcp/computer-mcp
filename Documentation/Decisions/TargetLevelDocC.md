# Target-level DocC

## Status

Accepted.

## Context

The package has an internal Swift implementation target shared by its two
executable products. Maintainer-facing target documentation should live with
the target it documents, while repository-level architecture and reference
material belongs under `Documentation/`.

## Decision

Place DocC source at `Sources/ComputerMCP/ComputerMCP.docc/`. Do not place
target API DocC catalogs under repository-level `Documentation/`, and do not
check in generated `.doccarchive` output.

## Consequences

- Symbol-level and target-level implementation documentation stays close to
  source without promising a public Swift SDK.
- Repository-level docs keep their architecture, decision, and reference roles.
- DocC archives can be generated by tooling without becoming source files.

## Alternatives Considered

- Root-level DocC catalog: rejected because the implementation target remains
  the clear owner of its Swift documentation.
- Checked-in `.doccarchive`: rejected because no publishing policy currently
  requires generated output in source control.
