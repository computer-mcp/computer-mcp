# Computer MCP, OpenAI Dots and Codex Remote

Choose by the job and execution boundary. These products can complement one
another; their capability and account requirements differ.

| Dimension | Computer MCP | OpenAI Dots | Codex Remote |
| --- | --- | --- | --- |
| Primary job | Direct, composable access to local tools | Always-on work with memory and proactive follow-through | Start, steer, approve and review coding tasks remotely |
| Execution | The chosen host runs registered capabilities; Codex is optional | A cloud agent with its own computer; it can delegate local Work or Codex tasks | Codex runs the task on the selected connected computer |
| Computers | Independent Computer MCP hosts connected to a compatible client | One personal computer at a time, alongside a separate cloud computer | Multiple connected computers/hosts; select where work runs |
| Interface | Typed MCP tools, registered CLI, Skills, builtins and Computer Use | Agent conversation, apps/plugins and delegated tasks | Coding conversations, commands, diffs and test output |
| Client and authority | ChatGPT or compatible MCP clients; per-host policy, approvals and audit | ChatGPT's agent, app and computer-access controls | Codex account/workspace and connected-host permissions |
| Strongest fit | General local capabilities across computers and clients | Cloud continuity, memory and proactive work | First-party remote Codex workflows |

Computer MCP does **not require a Codex task** to run ordinary registered
tools. This is an architectural distinction, not a claim of free or unmetered
usage. Client, model and vendor service terms still apply. OpenAI says Dot
conversations do not count toward ChatGPT usage limits; delegated Codex and
ChatGPT Work tasks count toward their applicable limits.
